# ELEMARKET Cloudflare R2 Storage

## Architecture

ELEMARKET depends on the provider-neutral `StorageProvider` interface.

```text
ELEMARKET
   |
   v
StorageProvider
   |
   +-- CloudflareR2StorageProvider
   |
   +-- future S3/B2 adapter
```

No marketplace domain module should import the R2 adapter directly.

## Render environment variables

Configure these as server-side secrets/environment variables:

```text
ELEMARKET_STORAGE_PROVIDER=r2
CLOUDFLARE_R2_ACCOUNT_ID=<Cloudflare account ID>
CLOUDFLARE_R2_ACCESS_KEY_ID=<R2 API token access key>
CLOUDFLARE_R2_SECRET_ACCESS_KEY=<R2 API token secret>
CLOUDFLARE_R2_BUCKET=<R2 bucket name>
```

Never expose the access key or secret to the browser.

## Cloudflare setup

1. Create an R2 bucket in the Cloudflare dashboard.
2. Create an R2 API token with the minimum required permissions for that bucket.
3. Copy the account ID, access key ID and secret access key into Render.
4. Set `ELEMARKET_STORAGE_PROVIDER=r2`.
5. Redeploy.

The adapter uses S3-compatible Signature V4 requests and does not add an AWS SDK dependency.

## Browser upload flow

1. Authenticated client creates a durable upload intent.
2. ELEMARKET validates purpose, ownership, MIME type and size.
3. Server creates a short-lived presigned R2 PUT URL with Content-Type, Content-Length and `If-None-Match: *` signed into the request.
4. Browser uploads directly to R2 using the returned required headers.
5. Client explicitly finalizes the upload.
6. Server reads the object, checks exact size/type and validates its file signature/structure before marking the intent `verified`.
7. Failed verification deletes the object; stale intents are cleaned by the scheduled cleanup endpoint.

The application server does not proxy normal upload bytes.

The application server does not proxy the file bytes.

## Supported purposes

All marketplace-managed uploads are capped at **560 KiB (573,440 bytes)**. Video uploads are not supported.

- `product-image`: JPEG/PNG/WebP, max 560 KiB
- `profile-image`: JPEG/PNG/WebP, max 560 KiB
- `business-document`: PDF/JPEG/PNG, max 560 KiB
- `dispute-evidence`: PDF/JPEG/PNG/WebP, max 560 KiB
- `order-attachment`: PDF/JPEG/PNG/WebP, max 560 KiB

Uploads are issued through a durable upload intent. The object must be finalized and pass size, Content-Type, and file-structure checks before application code treats it as verified. The presigned PUT also uses `If-None-Match: *` to prevent reuse of an upload URL to overwrite an already-created object.

## Important security rule

The presigned URL is temporary. Object keys are generated by ELEMARK and are never accepted as arbitrary user-controlled paths.

For private documents, use `createPresignedDownload()` from the server rather than exposing the R2 bucket publicly.
